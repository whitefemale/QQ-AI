# 连接器接入说明（OneBot 11 / NapCat）

更新日期：2026-10-31

> 本项目不接触 QQ 密码、不绕过验证码、不做设备指纹伪装或风控规避。登录、验证码和
> 平台风控完全由你本人和你安装的连接器负责。请只使用自己拥有并获授权管理的专用账号。

平台提供受管连接器页（`/connectors`），把「下载/校验/解压 → 启动官方安装器 → 启动
连接器 → 写配置 → 连接 → 诊断 → 身份确认 → 拉群」串成显式步骤。**每一步都不会在
后台静默执行**：安装器、NapCat 进程、配置写入都需要本机页面输入确认词。

必须区分以下事实，界面会分别显示证据与时间：

> 解压 ≠ 已安装 ≠ 安装器完成 ≠ QQ 已登录 ≠ WebSocket 已连接 ≠ 身份已验证 ≠
> 已收到真实群消息 ≠ 已成功真实回复。

整个 `/api/connectors/*` 只允许本机回环访问。即使开启 `ALLOW_REMOTE_ADMIN`，远程请求
也不能管理或触发本机连接器。

## 1. 受管目录与桌面目录选择

- 默认受管根目录：`<仓库根>/connectors/napcat/`，每个版本一个子目录；`connectors/`
  不进入 Git。
- 可用后端环境变量 `CONNECTORS_DIR` 指定其他根目录。API **不接受任意路径**。
- 桌面版可在连接器页点击「选择连接器目录」，通过系统目录选择写入设置；改动需要重启
  后端才生效。浏览器模式不能选择服务器目录，会诚实显示不可用。
- 平台只扫描该根目录内的候选安装，不扫描用户主目录或全盘。根目录外自行安装的
  NapCat 不会被接管，只能用「配置导入」或「高级手动设置」接入，显示为外部只读。

## 2. 下载、校验与解压（受管安装任务）

连接器页的安装区域可以：

1. 查询最近版本（只读取 Release 元数据，不下载）。
2. 输入确认词 `INSTALL` 后创建安装任务。
3. 查看阶段/进度/日志尾部，必要时输入 `CANCEL` 取消任务。

任务只做官方 Release 下载、SHA-256 校验、安全解压和 manifest 写入。成功后状态是
**安装包已解压（`installer_ready`）**，不是「已安装」。后端重启会把未完成任务标为
`interrupted`，需重新开始；平台不做断点续传或自动重试。

命令行入口仍然可用：

```powershell
# 只查看将下载的版本、资产、大小与 SHA-256，不下载
backend\.venv\Scripts\python.exe scripts\install_napcat.py --dry-run

# 下载、校验并解压官方 OneKey 包
backend\.venv\Scripts\python.exe scripts\install_napcat.py

# 指定版本或安装根目录
backend\.venv\Scripts\python.exe scripts\install_napcat.py --version v4.18.42 --dest connectors\napcat
```

默认脚本流程不会执行安装器。手工 `--launch` 仍要求交互式终端输入 `LAUNCH`；该路径
不属于受管页面流程，不提供前端入口。

## 3. 运行官方安装器

安装包解压后，在连接器页点击「运行安装器」，输入 `RUN INSTALLER`。平台会：

- 重新核对受管 manifest 与 `NapCatInstaller.exe` 的 SHA-256；
- 以固定路径、无参数、不提权方式新建可见控制台启动官方安装器；
- 记录审计时间，但**不代替你操作安装器**。

安装器是交互式第三方 GUI，可能联网下载 QQ、请求管理员权限或要求确认协议。完成后
回到连接器页点击「重新扫描」。只有检测到合格的 shell 布局，状态才会变为
「已安装未启动（`installed_not_started`）」。如果安装器退出但没有检测到 shell，
页面会如实显示，不会声称安装完成。

平台不强制关闭官方安装器，以免留下半安装状态；请在其窗口内完成或取消。

## 4. 启动、登录与进程归属

1. 点击「启动 NapCat」，输入 `START NAPCAT`。
2. 平台只启动受管目录内的固定 `napcat.bat`，经绝对 `cmd.exe`、无用户参数、新建可见
   控制台；批处理内容由第三方提供，平台不能审计其全部行为。
3. 用户自行在 NapCat/QQ 窗口中登录专用账号。平台不接触密码、验证码或登录界面。
4. 页面进入「运行中 · 登录未确认（推断）」只代表端口在监听且尚无身份证据，**不代表
   已登录**。
5. 点击「停止 NapCat」，输入 `STOP NAPCAT`，只会停止本次后端会话启动并仍跟踪的进程树。
   未跟踪的进程返回 `CONNECTOR_PROCESS_NOT_TRACKED`，请手动关闭；平台不会按端口或
   进程名杀进程，也不会停止外部启动的 NapCat。
6. 后端正常退出或重启都不会自动终止 NapCat，避免静默中断你的 QQ 会话；重启后的旧进程
   显示为归属未知/未受管。

启动前会检查拟用的本机端口。任一端口已被占用时返回端口冲突，不启动、不接管、不杀
外部进程。

## 5. 写配置并创建受管实例

确认 NapCat 进程已停止（写配置时若发现进程或端口仍在使用会被拒绝），在连接器页执行：

1. 打开配置预览。预览显示目标文件、将保留的未知字段、拟用回环端口和**掩码 Token**。
   默认从 3000/3001 起寻找空闲端口，跳过控制台端口、WebUI 端口和已配置端口。
2. 点击「写入配置」，输入 `WRITE CONFIG`。
3. 平台先把目标配置加密快照，再原子写入：
   - `network.httpServers` 增加/合并 `ai-group-friend-http`；
   - `network.websocketServers` 增加/合并 `ai-group-friend-ws`；
   - 两个条目共用同一随机 Token，保留其他服务器与未知字段；
   - 只监听 `127.0.0.1`。
4. 文件回读校验成功后，平台创建或更新一个关联账号/实例，Token 加密保存，
   `auto_connect=false`（不会静默连接）。
5. 任一步失败会恢复文件快照和旧实例 Token/端点；若恢复本身失败，返回
   `CONNECTOR_ROLLBACK_FAILED`，保留加密快照并停止自动配置。

只对文档验证过的版本（当前为 `v4.18.42`）允许自动写配置。其他版本标为
`not_verified`/`incompatible`，只能检测、手动配置、连接或通过配置导入接入，避免在
未知 schema 上静默破坏文件。

快照列表只显示元信息，不显示配置正文或 Token。可在进程停止、适配器离线时选择快照并
输入 `RESTORE CONFIG` 恢复；恢复会同时把快照中的 Token 重新加密写回关联实例。

## 6. 连接、诊断与身份确认

1. 启动 NapCat 并确认登录后，回到连接器页点击「连接」关联实例。连接成功但身份未确认
   时，实例是「已连接 · 身份未验证」，不会发送消息。
2. 点击「测试并诊断」：
   - 关联实例已在线时，**复用现有适配器**诊断，不建立第二条连接；
   - 未在线时，临时建立一条诊断连接，响应标注 `ephemeral_diagnostic`；若 NapCat 只允许
     单连接，请先断开其他实例，避免冲突。
   - 诊断不消费事件队列，不发送任何消息。
3. 确认诊断中的 QQ 登录身份后，点击「确认登录身份」并输入与当前在线适配器一致的 QQ 号，
   确认词 `CONFIRM IDENTITY`。不一致会被拒绝。
4. 只有身份确认后，「导入群列表」才会接受该身份；导入时必须再次填写同一个 QQ 号。
5. 导入的群默认关闭回复。请先保持「仅观察」，在受控群验证后再切换「仅 @ 回复」。

## 7. 如何阅读状态与诊断

受管状态包括：

| 状态 | 含义 | 是否成功 |
| --- | --- | --- |
| `installer_ready` | 包已解压，安装器尚未运行 | 否 |
| `installer_running` | 本次会话启动的安装器仍存活 | 否 |
| `installed_not_started` | 检测到合格 shell，进程未启动 | 否 |
| `waiting_login` | 端口在监听但无身份证据（推断） | 否 |
| `logged_in_not_connected` | HTTP 身份探测成功，WS 尚未连接 | 否 |
| `connected_traffic_unverified` | 适配器在线且身份已验证，但无真实收发证据 | 否 |
| `traffic_verified` | 身份确认后观察到非 Mock 持久化入站 + 成功出站 | 是（有证据） |
| `running_unmanaged` | 端口在听，但不是本会话进程 | 否 |
| `interrupted` | 任务/进程状态在重启后中断 | 否 |
| `external_readonly` | 外部安装或导入配置，只读 | 否 |
| `auth_failed` / `incompatible` / `unknown_error` | 鉴权失败 / 版本不兼容 / 未知错误 | 否 |

`traffic_verified` 只能来自身份确认时间之后的非 Mock 持久化入站消息与 outbox
`sent` 记录；安装成功、进程存活、WS 连接和诊断都不能触发它。它不是「自动化验收」，
只表示观察到真实往返证据。

连接诊断固定包含 9 项：

| 检查 | 含义 |
| --- | --- |
| 配置校验 | 地址格式、scheme、回环/私网策略 |
| WebSocket 握手 | 是否成功建立正向 WS |
| OneBot 鉴权 | Token 是否被动作通道接受；未填 Token 只会警告 |
| QQ 登录身份 | `get_login_info` 是否返回 `user_id` |
| 动作通道 | 无害 `get_status` 探测；不支持时可能降为警告 |
| 群列表读取 | `get_group_list`；失败只降为警告，不推翻身份验证 |
| 事件流/心跳 | 测试窗口内是否收到连接器推送的事件帧 |
| 真实入站消息 | 测试窗口内是否真的收到群消息；不等待、不伪造 |
| 真实发送 | **始终未验证**，因为诊断从不发送消息 |

`ok` 或 `identity_verified` 只代表连接与身份证据，不代表真实群收发已验证。

## 8. 兜底：配置导入与高级手动设置

无法自动检测或版本未知时，使用以下两条只读/手动路径：

- **配置导入**：连接器页选择 NapCat 的 `onebot11*.json`，输入 `IMPORT CONFIG`。平台只
  读取已启用的第一个本机/私网 HTTP/WS 服务，Token 加密保存且只返回掩码，创建
  「未验证」实例。不会写外部文件，也不会修改 NapCat 配置。
- **高级手动设置**：「QQ 接入」页面保留完整手动模式，可填写 WS/HTTP 地址、Token，
  执行连接测试与诊断。外部安装和导入实例在此模式下仍可连接，但受管页不会接管其文件。

## 9. 版本切换与回滚

- 升级采用**并存安装**：下载新版本到新目录，不覆盖、不删除旧版本；平台不自动更新。
- 在连接器页选择目标版本并输入 `SWITCH VERSION` 切换活动指针。切换前要求目标受管、
  shell 可识别，且旧活动版本进程已停止。
- 回滚 = 切回旧活动版本；旧版本目录与其配置保持不变。
- 若曾向新版本写入配置，失败时先恢复该版本快照，旧活动版本不受影响。

## 10. 卸载

本阶段不提供自动卸载/删除。请退出 NapCat 与控制台后，手动删除
`connectors/napcat/<版本>/`。NapCat 自身保存的 QQ 数据目录不一定在该文件夹内，请按
NapCat 文档单独处理；`data/` 中的数据不会被自动删除。删除前请确认没有需要保留的配置
快照或审计记录。

## 11. 故障排查

| 现象 | 检查 |
| --- | --- |
| 扫描不到安装 | 确认受管根目录、版本子目录、`napcat.bat`、`manifest.json`；外部安装尝试配置导入 |
| 运行安装器被拒绝 | 仅受管安装、manifest 与安装器 SHA-256 必须匹配 |
| 启动提示端口冲突 | 停止占用端口的程序；平台不会杀外部进程 |
| 写配置被拒绝 | 确认 NapCat 已停止、版本兼容、Token 加密密钥可用、全局未暂停 |
| 诊断失败/单连接冲突 | 若实例已在线，诊断会复用；未在线时会临时建连，先断开其他连接 |
| 实例「已连接 · 身份未验证」 | 检查 QQ 登录与 `get_login_info`；不要开启回复 |
| 身份确认失败 | 输入必须与当前在线适配器的 QQ 号完全一致，Mock 实例不支持 |
| 后端重启后无法停止 | 旧进程归属未知，请在系统层面手动关闭；平台不会按端口杀进程 |
| 恢复快照后 Token 不一致 | 恢复会同步实例 Token；若失败查看 `CONNECTOR_ROLLBACK_FAILED` |

## 13. 已知限制

- 本仓库只用进程内假服务器与假进程验证 OneBot 协议、安装任务和状态机；真实 NapCat
  安装器、真实 QQ 登录与真实收发未验证。
- NapCat 安装器可能联网下载组件、请求管理员权限或改变安装位置；平台只能显式启动它。
- NapCat 配置中的 Token 按协议以明文存在于其配置文件；平台只保证自身存储加密、接口
  掩码与日志脱敏，无法保证第三方文件权限。
- Windows 批处理与安装器行为由第三方提供；平台只能保证固定路径、无参数、可见控制台、
  用户确认与审计。
- 端口探测存在竞态；写配置前会二次检查，但运行后仍可能被其他程序占用。
- 平台不提供自动登录、二维码/WebUI 自动化、验证码绕过、设备指纹伪装、反检测、批量
  养号、自动加群/加好友、广告群发或限流规避。
