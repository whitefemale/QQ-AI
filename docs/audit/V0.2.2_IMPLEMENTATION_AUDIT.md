## 二、发现的问题

### P0-1 已有目标目录直接拒绝，无法复用/修复

- 位置：`scripts/install_napcat.py::install`、`backend/app/connectors/jobs.py::start_install`
- 复现：安装一次后再次点击安装；或上次解压后残留同版本目录。
- 根因：`target.exists()` 一律抛出 `CONNECTOR_TARGET_EXISTS`；job 层也预先拒绝。
- 影响：重复点击、失败重试、残缺目录恢复全部不可用。
- 修复：分类为「完整同版本 / 受管但损坏 / 未知或非受管 / 被占用」；完整同版本重新校验后
  复用；受管损坏目录隔离到 `.quarantine-*` 后原子切换；未知目录拒绝且不触碰。

### P0-2 截断/损坏 ZIP 的错误分类不稳定

- 位置：`safe_extract_zip`
- 复现：截断 `NapCat.Shell.zip` 会触发 `BadZipFile`；某些损坏的中央目录会触发
  `EOFError`、`RuntimeError` 或 `NotImplementedError`。
- 根因：只捕获 `BadZipFile`，其他异常会以“未预期异常”结束，用户看不到可操作原因。
- 修复：统一捕获 ZIP 解析异常；解压前执行完整性探测；限制异常压缩比；所有失败只清理
  本次 staging。

### P0-3 下载没有重试与速度/中断语义

- 位置：`download_asset` / `install`
- 根因：单次请求；失败直接终止。界面只能看到失败，不能区分校验失败与网络中断。
- 修复：固定次数、带退避的下载重试；每次失败删除临时文件；事件携带已下载字节、总字节
  与可计算速度；最终仍失败时返回稳定错误码，绝不把残留文件当成功。

### P0-4 普通用户仍被迫填写 WebSocket/HTTP 地址与端口

- 位置：`frontend/src/views/AccountsView.vue` 新建账号对话框；
  `backend/app/connectors/manager.py::apply_config` 已经能自动分配端口、生成 Token 并创建实例。
- 根因：自动能力只在连接器页面单独使用，账号创建仍以手动字段为默认入口。
- 修复：向导新增 `POST /api/onboarding/actions/auto-configure-connector` 与一键动作；
  账号页以“自动接入（推荐）”为主路径，手动填写降级为“高级手动新建”。自动配置由
  后端分配地址/端口，普通用户无需手填；高级手动字段仍可编辑，但标注仅限高级用户。

### P0-5 向导只读，2/8 进度误导

- 位置：`backend/app/services/onboarding_service.py`、`backend/app/api/onboarding.py`、
  `frontend/src/views/OnboardingView.vue`
- 根因：向导只返回状态，没有动作；进度按 `done/8` 计算，Mock 和“需操作”步骤被混在同一
  进度条中；步骤缺少指导文档要求的状态字段。
- 修复：后端为每步补齐 `status/started_at/completed_at/attempt_count/last_error_code/
  last_error_message/evidence/can_retry/next_action`；Mock 不计真实；前端使用后端
  `next_action`，进度只统计真实完成步骤，并明确当前唯一主操作。

### P1-1 安装器 / Shell / 进程 / WebSocket / QQ 登录状态易混淆

- 位置：`state_engine.py`、连接器页。
- 现状：底层状态已分离；页面仍可能把下载任务完成、安装器已启动、Shell 未安装等文案混排。
- 本轮状态：**未完成七段式卡片改造**。已在向导中明确“已安装 Shell 不等于可收发”，
  并把“连接器准备”完成条件收紧为存在真实 OneBot 实例；连接器页本身仍使用既有状态字段。

### P1-2 诊断信息缺少行动指引

- 位置：`connection_diagnostics.py`、`DiagnosticsView.vue`。
- 本轮状态：**未实现统一的诊断 `next_action` 摘要**。接入向导已提供步骤级动作；诊断页
  保持原有只读证据，不触发新的模型/连接器请求。列为后续改进。

### P2 签名与自动更新

- 未实现；继续在发布文档中标注未签名、无自动更新。
