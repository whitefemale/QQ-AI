# 安全说明

本文档描述 AI 群友 P0 MVP 的安全边界、已实现的防护、残余风险与事件响应流程。它不是对外部连接器、模型服务或宿主机安全的保证。

## 1. 安全目标

1. 不接触 QQ 密码；QQ 登录只发生在用户自行安装并控制的连接器中。
2. Token、API Key 不落明文：数据库中为 Fernet 密文，接口只返回掩码，日志脱敏。
3. 管理面默认仅本机可用；远程管理必须显式开启并携带管理 Token。
4. AI 只在用户明确启用的白名单群、按保守策略回复；全局暂停始终优先。
5. 群消息、媒体文本、工具结果一律视为不可信输入，不能成为系统/管理员指令。
6. 不存在任意命令执行、任意文件读写、任意 URL 请求或第三方插件代码执行。唯一例外是
   第 5 节列出的受管连接器固定命令与固定配置文件，均需本机确认词、固定路径、无用户
   参数，不构成通用执行或读写接口。
7. 备份可校验、恢复需二次确认；不包含加密密钥、媒体与日志。
8. UI 诚实标注能力状态，绝不把 Mock 或接口占位展示为真实能力。

## 2. 信任边界与资产

### 受信任

- 宿主机操作系统与本地用户账户。
- 本项目后端进程与其本地 SQLite 数据库。
- 用户通过控制台进行的管理操作。

### 不完全受信任

- QQ 群消息、群成员昵称、图片/语音/文件元数据。
- 连接器（NapCat 等）传入的事件与 action 响应。
- 模型输出、工具调用参数与结果。
- 第三方模型服务（配置后会将提示词内容发送出去）。
- 远程浏览器与反向代理（若开启远程管理）。

### 需要保护的资产

| 资产 | 位置 | 保护 |
| --- | --- | --- |
| OneBot Token | SQLite 加密字段 | Fernet；接口掩码；日志脱敏 |
| 模型 API Key | SQLite 加密字段 / 可选 `.env` | 同上；推荐只在控制台填写 |
| `CREDENTIAL_ENCRYPTION_KEY` | `.env` 或进程环境 | 不进数据库、不进备份、不进日志 |
| 管理 Token | `.env` / 进程环境 | 仅远程管理时使用；不进前端持久存储 |
| 群聊消息与人格数据 | SQLite | 依赖宿主机与磁盘保护；非端到端加密 |
| 备份文件 | `data/backups/` | 含数据库（含凭证密文）；按敏感文件保护 |
| 审计日志 | SQLite | 记录管理动作，不含明文密钥 |

> SQLite 中只有凭证字段加密，消息、人格与配置本身不是数据库级加密。若设备丢失风险较高，请启用操作系统全盘加密（如 BitLocker）并限制本地账户权限。

## 3. 部署边界

### 默认安全配置

- `APP_HOST=127.0.0.1`，仅监听回环地址。
- 管理 API 拒绝非回环请求（`REMOTE_ADMIN_FORBIDDEN`），除非同时满足：
  - `ALLOW_REMOTE_ADMIN=true`；
  - 配置强 `ADMIN_API_TOKEN`；
  - 请求携带 `X-Admin-Token` 或 `Authorization: Bearer ...`；
  - Token 使用常量时间比较。
- CORS 默认只允许本机 Vite 开发地址；`CORS_ORIGINS` 必须是显式来源列表（带 scheme），`*`、空项或无 scheme 会在启动时被拒绝，不会静默放行。
- `Host` 头受 TrustedHost 校验：默认允许 `127.0.0.1`、`::1`、`localhost` 与测试客户端主机名。反向代理或远程部署必须在 `ALLOWED_HOSTS` 中加入代理域名，否则返回 400 `Invalid host header`。显式 `*` 会关闭校验，只应在完全受控环境使用。
- 所有响应带 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` 与限制设备能力的 `Permissions-Policy`；HTML 页面额外带 CSP（`default-src 'self'`、无内联脚本、`object-src 'none'`、`frame-ancestors 'none'`）。Swagger 文档页因依赖 CDN 与内联脚本而豁免 CSP，JSON 响应不设 CSP。本地 HTTP 不发送 HSTS。
- OneBot WS/HTTP 地址默认只允许回环或私网 IP；公网地址必须显式启用 `allow_remote`。
- 模型 Provider 的 `base_url` 会拒绝云元数据地址（`169.254.169.254`、`100.100.100.200`、`metadata.google.internal` 等）、链路本地、组播、未指定与共享地址；允许回环与 RFC1918 私网以支持自建模型。适配器不跟随重定向，每请求有显式超时。
- **本机管理请求不校验管理 Token**，安全边界是操作系统用户与本地回环网络。不要在同一台机器上运行不受信任的本地程序并让它访问 8000 端口。

### 部署要求

1. **不要**把 8000 端口直接暴露到公网。
2. 远程管理应通过 HTTPS 反向代理，并额外做访问控制（VPN、mTLS、IP 白名单等）。
3. 反向代理必须正确设置客户端 IP 头；否则本机判定可能基于代理地址，导致边界判断失真。
4. 控制台与后端应只运行在受信任的本地网络中。
5. 不要把 CORS 配成 `*`。当前实现使用固定来源列表。
6. 不要把 `.env`、`data/`、备份文件放入同步盘或公开仓库。

### 桌面壳（Electron）边界

- **渲染进程不受信任**：窗口启用 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，并显式固定 `webSecurity: true`、`allowRunningInsecureContent: false`；不向页面暴露 `ipcRenderer`、`fs`、`child_process` 或任意路径/命令。
- **权限边界**：默认会话的权限请求/检查处理器只允许 `clipboard-sanitized-write`，摄像头、麦克风、定位、通知、MIDI、全屏等一律拒绝；设备权限处理器固定拒绝；`will-attach-webview` 一律阻止。
- **启动页 CSP**：`shell/index.html` 的 CSP 为 `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`。
- **最小 IPC 白名单**：仅暴露应用信息、设置读取/更新、启停/重启后端、打开白名单目录、选择连接器目录、打开固定 Releases 页、打开控制台、退出与状态/日志订阅。`openFolder` 只接受 `data` / `logs` / `backups` / `connectors`；设置更新校验字段类型，拒绝未知字段；连接器目录只允许空值或绝对路径，选择对话框不读写文件、不执行命令。
- **导航限制**：只允许本地启动页（`shell/index.html`）与当前本机后端的 `http://127.0.0.1:<port>`；阻止其他导航、重定向和新窗口。外链仅允许固定的 GitHub Releases 地址并通过系统浏览器打开。
- **子进程（源码版）**：主进程用固定参数启动 `backend/.venv` 中的 Python 与 uvicorn；命令、CWD 和环境变量由主进程代码决定，渲染进程只能请求“启动/停止”，不能传入任意命令、路径、URL 或环境变量。
- **子进程（安装版）**：主进程以固定参数 `[]` 直接启动 `resources/backend/aiqf-backend.exe`。该入口固定监听 `127.0.0.1`，端口与日志级别只接受白名单/范围校验；不提供 reload、workers 或命令行参数。受管 NapCat 安装器也只以后端生成的固定参数执行冻结 exe，不使用 `shell=True`。
- **数据目录**：安装版默认 `userData/data` 与 `userData/connectors/napcat`；源码版默认仓库 `data/` 与 `connectors/napcat/`。用户可在设置中选择其他目录，但这些路径只用于传给后端与打开四个白名单子目录，不作为任意文件读写接口。修改后需重启后端。
- **密钥与日志**：桌面版不读取密钥明文、不回显、不记录 `.env` 内容或 `CREDENTIAL_ENCRYPTION_KEY`；向导只检查密钥键是否存在且非占位值。安装版首次启动在 `userData/.env` 用 `crypto.randomBytes` 生成独立密钥，尝试设置 `0600`，绝不覆盖已有文件；源码向导不修改仓库 `.env`。桌面日志写入 `userData/logs/desktop.log`，后端日志由应用自身的脱敏过滤器处理。
- **构建与分发**：安装包不包含 `.env`、数据库、日志、备份、媒体或连接器；构建脚本不读取本机 `.env`。`release/BUILD_INFO.json` 提供 SHA-256，但安装包**未签名**，用户必须核对哈希并自行评估 SmartScreen 提示。没有自动更新、后台下载或远程命令。
- **进程清理**：退出时先停止受管后端；Windows 超时后使用 `taskkill /PID <pid> /T /F` 结束进程树。外部后端只断开连接，不会被桌面版结束。
- **信任边界**：源码版复用受信任的本机 Python/Node 与仓库代码；安装版复用随包分发的冻结后端与前端。两者都不是免依赖沙箱，也不改变“本机管理请求不校验管理 Token”的既有边界。

### 接入向导、诊断与复制边界

- `GET /api/onboarding` 与 `GET /api/diagnostics` 都是**只读**：不写审计、不触发模型/QQ/连接器网络或进程动作，不读取或返回日志正文。需要新的连接诊断必须由用户在 QQ 接入或连接器页主动执行。
- 诊断使用显式 allowlist 构造新对象，不把数据库对象、审计 details、事件 payload 或异常对象直接透传；不返回 Token、API Key、Authorization、Cookie、QQ 号/昵称/头像、群号/群名、消息正文、媒体内容、提示词、连接器/数据/日志路径、PID、端口、WS/HTTP 端点、模型 Base URL/模型 ID/Provider 名称或密钥掩码。
- 前端「复制脱敏诊断摘要」只复制后端 `text`；连接诊断的复制文本还会再把 URL、文件路径与长数字标识替换为占位符。剪贴板失败会显示错误并保留可选文本，不静默失败。
- 复制内容仍可能包含运行环境、计数、枚举状态与动作名。分享前请自行检查，不要把本机日志整份公开。
- 健康探测只请求本机 `/api/health`，不携带管理 Token、模型 Key 或连接器 Token；失败只更新界面健康状态，不停止、不重启、不结束任何进程。

## 4. 凭证与密钥

### 加密方式

- 使用 `cryptography.fernet.Fernet`（AES-128-CBC + HMAC-SHA256 的 Fernet 结构）做应用层加密。
- 密文带 `enc:v1:` 前缀，存储在 SQLite 字段中。
- `CREDENTIAL_ENCRYPTION_KEY` 缺失或格式错误时，保存/使用凭证会返回 `CREDENTIAL_KEY_MISSING` / `CREDENTIAL_DECRYPT_FAILED`，不会退化为明文。
- 数据库中的密钥字段不会通过 API 返回；列表和详情只返回 `api_key_configured` 与掩码。

### 密钥管理要求

1. 使用 `scripts/gen_keys.py --write` 生成随机的 `APP_SECRET_KEY` 和 Fernet 密钥。
2. 离线保存一份 `CREDENTIAL_ENCRYPTION_KEY` 的恢复副本（密码管理器或物理介质），但不要和数据库备份放在同一位置。
3. **轮换密钥会使旧凭证无法解密。** 轮换前请记录所有需要重新填写的 OneBot Token 与模型 API Key；轮换后重新录入。
4. `.env` 权限应限制为当前用户可读写；`.gitignore` 已排除 `.env`、密钥、数据库与备份。
5. 不要在终端、截图、Issue 或日志中粘贴密钥。`gen_keys.py --write` 不回显密钥本身。

### 环境变量中的模型 Key

`DEFAULT_LLM_API_KEY` 仅用于临时调试，属于未加密的 `.env` 内容。正式使用请删除该变量，在控制台「模型 API」中填写；数据库保存的是密文。

## 5. 连接器安全（OneBot 11 / NapCat）

- 本平台不登录 QQ，不保存 QQ 密码、Cookie 或设备指纹。
- 连接器地址必须为 `ws://`/`wss://`（WS）与 `http://`/`https://`（HTTP）；默认仅回环/私网地址。
- 主机名解析：只接受 `localhost` 或 IP 字面量；不接受任意域名指向公网。
- Token 通过 `Authorization: Bearer` 等方式发送给连接器；事件与 action 响应均不执行内容。
- 未知消息段保留为 `unknown`，不会拼接成可执行指令。
- 发送超时等无法确认结果的情况标记为 `unknown`，**不自动重发**，避免重复消息。
- WS 握手成功只进入 `connected_unverified`；必须成功读取 `get_login_info` 的
  `user_id` 才进入 `online`。未验证身份时不发送、不拉群、不导入群。
- 心跳、lifecycle 与发送成功都不能把未验证连接提升为在线；身份查询失败会保留错误码
  并允许用户重连或重新诊断。
- 连接器本身的漏洞、版本兼容性、账号风控属于外部风险；请保持连接器更新，并使用专用账号。

### 第三方连接器下载与执行（NapCat）

- 本仓库**不捆绑、不提交、不再分发** NapCat 二进制；`connectors/` 被 `.gitignore` 忽略。
- `scripts/install_napcat.py` 只从 NapCat 官方 GitHub Release 读取资产，资产名固定为
  `NapCat.Shell.Windows.OneKey.zip`。
- 下载只允许 HTTPS 且主机在白名单内（`api.github.com`、`github.com`、
  `release-assets.githubusercontent.com`、`objects.githubusercontent.com`）；拒绝
  userinfo、IP 字面量、非 443 端口，并逐跳校验重定向、最多 5 次。
- 资产必须提供 `sha256:<64 hex>` digest；下载同时计算 SHA-256 并核对
  `Content-Length`、Release 声明的 size、实际字节数与 digest，任一不符即删除临时文件。
- 解压拒绝绝对路径、盘符、`..`、空/`.` 组件、NUL、控制字符、反斜杠、冒号/ADS、
  Windows 保留名、符号链接、特殊文件与大小写不敏感重复路径；限制 200 个条目、
  单文件/总量 50 MB；必须存在 `NapCatInstaller.exe`。
- 目标目录已存在时拒绝覆盖；全部校验通过后才原子重命名。
- 默认**不执行**安装器。`--launch` 必须运行在交互式 TTY，用户输入 `LAUNCH`，并重新
  校验安装器 SHA-256；以固定路径、无参数、`shell=False`、无提权方式启动。
- 脚本不登录 QQ、不写 NapCat 配置、不启动 WebUI、不发送消息。
- NapCat 使用自定义 Limited Redistribution License；这不是标准开源许可证。脚本会尝试
  保存官方 `LICENSE*` 并记录 blob SHA；获取失败时明确标记 `unavailable`，不声称已审阅。
  使用或再分发前请自行阅读官方条款；本仓库不授予任何再分发权利。
- 安装器可能联网下载组件或请求系统权限，属于第三方程序行为，需用户自行确认。

### 受管连接器页（阶段 2）

- **仅本机**：整个 `/api/connectors/*` 要求回环客户端、回环 `Host`，拒绝非本机
  `Origin`；该守卫**独立于** `ALLOW_REMOTE_ADMIN`。即使开启远程管理，也不能读取本机
  路径或触发本机第三方程序。
- **确认词**：安装 `INSTALL`、取消 `CANCEL`、运行安装器 `RUN INSTALLER`、启动
  `START NAPCAT`、停止 `STOP NAPCAT`、写配置 `WRITE CONFIG`、恢复快照
  `RESTORE CONFIG`、切换版本 `SWITCH VERSION`、导入 `IMPORT CONFIG`、确认身份
  `CONFIRM IDENTITY`。缺失或大小写不匹配返回 `CONNECTOR_CONFIRMATION_REQUIRED`。
- **固定执行边界**：只允许后端脚本、受管 `NapCatInstaller.exe`、受管 `napcat.bat`
  （经绝对 `cmd.exe /d /s /c`）与绝对 `taskkill.exe`。固定参数、`shell=False`、无提权；
  不提供任意命令、参数、URL 或路径接口。
- **路径边控**：只扫描 `CONNECTORS_DIR`；拒绝符号链接/junction、越界路径、未知布局。
  API 不接受安装路径，桌面目录选择只写设置并在重启后生效。
- **进程所有权**：只保存当前进程内存中的 `Popen` 与启动时间，不持久化 PID。停止只结束
  本会话仍跟踪的进程树；未跟踪、后端重启前启动或外部启动的进程一律拒绝停止，引导手动
  关闭。启动前检测端口冲突，不接管、不杀外部进程。
- **配置写入**：只写受管且版本兼容安装中的 `config/onebot11*.json`；写入前要求进程停止
  并二次检查端口。先加密快照（Fernet），再原子替换并回读校验；失败恢复文件与实例
  Token，恢复失败返回 `CONNECTOR_ROLLBACK_FAILED`。快照正文与 Token 不返回 API、不写
  日志或审计。
- **秘密隔离**：安装/启动子进程使用环境允许列表，不继承 `CREDENTIAL_ENCRYPTION_KEY`、
  `APP_SECRET_KEY`、`ADMIN_API_TOKEN`、数据库 URL；NDJSON 事件与日志尾部做脱敏。
- **全局暂停**：暂停时拒绝启动、运行安装器与写配置；下载任务仍需单独用户确认。
- **无自动更新/卸载**：不检查更新、不后台下载执行、不删除安装。升级采用并存目录 +
  显式 `SWITCH VERSION`；卸载为文档化手动步骤。
- **残余风险**：NapCat 安装器与批处理的实际行为由第三方决定；NapCat 配置文件中的 Token
  按协议明文保存，平台无法保证第三方文件权限。请限制受管目录的本地访问。

### 建议

1. 连接器只监听本机/内网，不要暴露公网。
2. 使用长度足够、随机的独立 Token，不与其它服务共用。
3. 发现验证码、登录异常、频繁掉线或被限制时，立即全局暂停、断开连接器并停止自动回复。
4. 先在「仅观察」模式验证事件解析与群白名单，再开启「仅 @ 回复」。

## 6. 提示注入与不可信数据

群消息、昵称、引用内容、图片/语音元数据、OCR 文本、ASR 转写、工具结果和模型输出都可能包含恶意指令。当前实现的防护：

- 系统安全/权限提示位于分层提示词的最高优先级。
- 群消息与工具结果以「不可信数据」包裹，不作为系统或管理员指令。
- 管理命令仅接受白名单管理员 ID 或由控制台发起，群内普通消息不能触发管理操作。
- 工具权限引擎默认禁止高风险工具；群默认禁用工具。
- 不提供 Shell、PowerShell、Python 执行、任意文件读写、任意 URL 请求工具；受管连接器的
  固定命令/配置例外只能由本机管理员页面与确认词触发，群消息、模型或远程管理面都无法
  调用。
- 模型回复在进入发送队列前进行长度与内容审查。
- 媒体缺少识别能力时只给降级提示，不伪造识别结果。
- 长期记忆作为不可信历史资料单独标注注入，不能成为系统或管理员指令；只读取当前群与当前发送者的记忆，绝不跨群。短期上下文同时按账号与群/私聊过滤，避免相同 `conversation_id` 串上下文。
- 记忆写入、AI 回复生成、人工批准与 outbox 发送共用同一组敏感模式，拒绝疑似密码、验证码、证件号、银行卡号与 API Key；`sensitive` 记忆不会自动注入；排除成员与被排除成员的成员级记忆不参与检索。
- 模型输出在入队前检查疑似凭证；命中后拦截为 `sensitive_output`。清洗后为空则拦截为 `empty_output`。命令回复与人工批准同样经过清洗、长度与敏感检查，不会绕过。
- AI 记忆候选提取可由控制台手动触发，或在群内显式开启后台增量提取；模型输出只进入 `pending` 候选，**绝不自动创建正式记忆或注入提示词**；人工批准/拒绝均写审计。
- 后台提取默认关闭，必须同时开启长期记忆；只处理 `enabled`、未暂停且在全局未紧急暂停的群，按时间 + 消息 ID 双字段游标从旧到新增量读取，无新消息不调用模型；失败只记录脱敏错误且不推进游标。
- 提取只读取当前群最近入站消息，排除已标记“排除记忆”的成员；候选必须引用真实消息 ID，敏感内容、未知成员、低置信度与重复候选会被丢弃，不保存模型推理过程。
- Mock 模型生成的候选记录 `is_mock=true` 并在界面标注，仅用于演示；批准 Mock 候选前必须确认它不是真实模型的理解结果。

**残余风险**：提示注入无法被完全消除；模型仍可能被诱导输出不当内容。请保留人工审核、限速、白名单和全局暂停，并避免给 AI 高权限工具。

## 7. 消息流水线与发送安全

- 硬规则先于模型调用：去重 → 自身消息过滤 → 账号/群白名单 → 全局暂停 → 安静时段 → 成员静音 → 冷却/频率/连续回复限制 → 空消息与重复刷屏启发式。
- 回复模式为观察、仅 @、手动确认、自动回复与高级关键词。**新建与导入的新群默认观察**，不生成回复；已有群不被静默迁移。
- 手动确认模式下生成的回复只进入 `pending_approval`，`send_due` 永不派发它。批准时先重新执行全局暂停、账号/群启用与暂停、安静时段、成员静音、群级与每成员限频、长度与敏感检查，再用条件 UPDATE 原子切换到 `pending`；重复/并发批准只有一个成功，其余 409。
- 跨群上下文隔离；群配置绑定账号，防止错群发送。
- 消息唯一约束 `(account_id, platform_message_id, direction)` 防止重复事件重复回复。
- outbox 使用幂等键；`unknown` 状态不重发；明确可重试错误有次数上限；连续失败达到阈值自动暂停。
- 回复长度受全局与群级上限约束；控制字符、全员 @ 与高风险内容会被清理。群级上下文条数可覆盖全局值，并保留总字符上限。
- 发送前最终门禁重新检查全局暂停、账号/群启用与暂停、安静时段；人工批准复用同一组检查。
- 每人限频按 outbox 中 `sent`/`unknown` 的 AI 回复统计；待审核草稿不占额度，命令回复不计入。缺失来源成员的历史记录不归属成员额度，群级限制仍生效。
- 重复刷屏保护是进程内启发式：同一会话同一发送者 60 秒内至少 4 条完全相同的非空文本会被拦截，重启清零，不能识别所有第三方机器人。
- 任何硬检查失败都记录拦截原因，不发送消息。
- 全局暂停期间不调用模型、不派发自动发送队列；管理员命令仍可执行，但同样受输出清洗约束。

## 8. 工具与插件

- 内置工具注册表固定为 `calculator` 与 `current_datetime`，回归测试断言不存在 shell、文件或 HTTP 工具；测试执行也经过参数校验、超时与权限引擎。
- 当前**不加载、不执行第三方插件代码**。插件目录中的清单只做校验、登记、健康状态展示与权限批准。清单中的 `healthcheck` 只保存为声明，不会执行第三方健康检查或发起任意网络请求；批准高风险权限也不会启用第三方运行时。
- 插件 Manifest 需要版本兼容；不兼容或加载失败会被隔离并显示错误。
- 不允许通过群消息动态注册工具或修改权限。
- 插件记录通过 `execution` 与 `runtime_requirements` 如实表达执行能力：内置插件为 `builtin_in_process`；第三方插件为 `not_executed`，并列出未来开放执行前必须同时满足的八项要求——独立沙箱、权限清单、用户确认、签名/来源校验、超时、资源限制、审计、停用即时止损。任一要求未实现都不得开放执行入口；当前实现全部未实现，`PluginRuntime` 是显式拒绝的占位，调用返回 `OPERATION_PLANNED`。
- `GET /api/extensions/capabilities` 只读汇总五类契约（聊天适配器、模型 Provider、媒体 Provider、工具、插件）的接口、执行方式、流水线依赖与安全保证；不触发 Provider、连接器、模型或第三方动作，也不写审计。

### 8.1 扩展停用与任务止损

- 媒体 Provider 的记录列出其负责的能力（按 Provider 类型推导并合并显式能力）。停用 Provider 后，若某能力不再有任何启用的可用 Provider，该能力下所有 `queued` 与 `running` 任务立即置为 `cancelled`，错误码 `PROVIDER_CAPABILITY_MISSING`。
- 运行中的 Provider 调用无法强制中止上游计费，但其迟到的成功结果在保存前会再次检查任务状态并被丢弃；迟到失败也不能覆盖已取消状态。测试覆盖排队与在途两种场景。
- 停用响应的 `cancelled_jobs`、`cancelled_capabilities` 与可选 `cancellation_error` 来自真实数据库操作；失败会如实报告，不伪装成功。审计 `provider.media.toggle` 记录 actor、取消数量与能力。
- 手动取消任务支持 `queued` 与 `running`，写 `media.job.cancel` 审计；重试仅在任务失败且仍有可用 Provider 时允许，否则返回 400，写 `media.job.retry` 审计，避免把任务重新排入不会执行的能力队列。
- 新增聊天适配器通过 `QQAdapterFactory` 注册并实现 `BaseQQAdapter` 接口，消息流水线与 outbox 不感知具体协议；未实现的能力必须在 `AdapterCapabilities` 中为 `false`，不得由业务层假设。

## 9. 媒体与模型数据

- 当前版本没有真实视觉/OCR/ASR/TTS/Embedding/视频理解 Provider；媒体契约与任务队列已实现，但 Provider 均为确定性 Mock，界面显示 `mock_only` 或 `unconfigured`。
- 能力概览通过 `execution` 区分「任务队列执行」与「仅接口契约」：`audio.synthesize`、`media.inspect`、`text.rerank`、`video.describe` 只有接口与 Mock，队列不会调用；即使启用对应 Mock，任务也会以 `PROVIDER_CAPABILITY_MISSING` 失败并如实显示，不产生伪造输出。
- 不上传媒体到外部服务；真实 Provider 属于后续能力。媒体片段只保存内部 `media_ref` 与安全元数据，不保存易过期 URL 或本地绝对路径。
- 图片/语音片段在流水线中只入队，由应用内后台 worker 处理，不阻塞 QQ 事件，也不在请求路径中等待外部模型。
- 媒体用量只记录 Provider、能力、请求/成功/失败、延迟、Mock 标记与外部费用完整性；不记录媒体内容、转写文本或提示词。Mock 外部费用记 0，真实/未知记 `null`。
- 配置真实 LLM 后，筛选后的上下文、人格提示词与群规则会发送给该模型服务。请阅读服务条款并评估数据跨境、留存与合规要求。
- 群级备用模型是**显式**配置：仅当主 Provider 发生调用错误时才重试一次，同一请求会发送到你配置的备用模型服务；请确认两个服务的数据政策。预算超限、全局暂停、Provider 禁用/缺失、本地配置缺失或凭证解密失败不会触发回退，避免绕过安全与费用控制。
- **真实主模型失败时不会回退到 Mock 备用模型**：若主 Provider 非 Mock、备用为 Mock，回退被拒绝并返回 `PROVIDER_FALLBACK_MOCK_FORBIDDEN`，不会产生掩盖真实故障的模拟回复。Mock→Mock 回退不受影响。
- 安全重试只针对 429、5xx 与连接建立失败/连接超时；读/写超时与协议中断默认不自动重试（`LLM_RETRY_AMBIGUOUS_TIMEOUTS=false`），避免请求已被计费后重复发送。认证、额度、模型不存在、参数错误、预算与取消永不重试。重试只重发单次模型请求，不重放工具执行或 QQ 消息。
- 429 的 `Retry-After` 会被解析；超过 `LLM_RETRY_AFTER_MAX_SECONDS` 不再自动等待。HTTP 客户端不跟随重定向，避免凭证被带往未配置的主机。单进程内每个 Provider 有并发与最小间隔保护，这不是分布式限流，多实例部署会各自计算。
- 测试调用也是真实计费调用（Mock 除外），经过预算检查并写入用量；单次尝试、不自动重试、不回退。取消端点只能停止本地等待，**不能保证服务商停止生成或停止计费**；浏览器断线不会自动取消服务端任务。
- 测试证据仅持久化白名单元数据与截断脱敏预览，不保存 API Key、请求头、完整提示词或完整响应体。修改配置敏感字段或显式清空 Key 会清除旧证据，避免“旧测试通过”误导新配置。Provider 接口响应、审计与日志均不含明文 Key。
- 模型调用的输入/输出 Token、耗时、错误类型与本地估算费用会记录在本地用量表中；费用按你填写的单价计算，不是服务商账单，未配置单价时不会生成伪造金额。
- 费用预算启用后，未配置单价的非 Mock Provider 会被阻断调用（`BUDGET_EXCEEDED` / `cost_unavailable`），避免无法计费的调用绕过费用上限。
- 用量趋势只聚合本地 `llm_usage` 元数据，按配置时区在应用层分桶；不额外调用外部服务。未知成本保持 `null`，不会补成 0。
- 预算告警事件只包含策略作用域、指标、用量、上限与比例，不含消息正文或凭证；每个新事件写审计并通过 SSE 发布。告警是通知，不改变「达到上限即阻断」的强制行为。
- 用量 CSV 只导出调用元数据（时间、Provider、模型、Token、延迟、估算费用、状态等），**不导出消息正文、提示词、模型回复、API Key、Token 或任何凭证**。文本字段做公式注入前缀防护；导出使用 `no-store` / `nosniff` 响应头，并写入审计 `usage.export`。
- 消息 CSV 导出**包含消息正文与发送者/群标识**，属于敏感数据；导出文件不包含 segments/媒体引用、提示词、模型输出或凭证。文本字段做公式注入前缀防护，最多 50,000 行；导出使用 `no-store` / `nosniff` 与 `attachment` 响应头，审计 `message.export` 只记录行数、筛选条件与 `has_search`，不记录搜索词或正文。
- Provider `base_url` 校验为语法与字面量级：拒绝元数据、链路本地、组播、未指定与共享地址，同时允许回环与私网。**不做 DNS 解析**，因此仍存在 DNS rebinding 残余风险（恶意域名在保存后解析到内部地址）。请只配置可信模型服务；适配器不跟随重定向、每请求显式超时，可降低但不能消除该风险。
- 提示词预览做脱敏后仅用于本地调试。

## 10. 备份、恢复与数据生命周期

- 备份是数据库一致性快照，包含加密后的 Token/API Key 密文，**仍然属于敏感文件**。
- 备份不包含：媒体文件、日志、`CREDENTIAL_ENCRYPTION_KEY`。
- 每个备份带 SHA-256 与 SQLite `PRAGMA integrity_check`；恢复前强制校验。
- **Schema 门禁**：恢复预览与执行都会比较备份的 Alembic 版本与当前代码 head。备份与 head 都已知且不一致时判定 `incompatible`，恢复返回 409 `BACKUP_SCHEMA_INCOMPATIBLE`，**在创建安全备份之前中止**，不改数据库；缺少版本信息时标记 `unknown`，允许但显著警告（仅适合开发/测试库）。备份版本等于 head 时，即使当前库版本不同也允许恢复。
- 恢复流程：全局暂停 → 校验 → 预览（含 Schema 与应用版本） → 输入 `RESTORE` → 自动安全备份 → 断开连接器 → 同目录暂存并原子替换数据库 → 写入全局暂停并保持。恢复后暂停不依赖备份快照中的旧状态，避免恢复到未暂停配置后立即发送。暂存副本可避免复制中途失败截断当前库；Windows 文件占用会做有限重试，失败时保留原库并提示安全备份 ID。成功恢复审计记录 `schema_status` 与三份 Schema 版本。
- 删除备份需要 `?confirm=DELETE` 并写 `backup.delete` 审计（文件名与 ID，不含完整路径）。
- 恢复后必须确认群配置与凭证可用，再手动解除暂停。
- **自动清理默认关闭**。管理员可在设置页显式开启，也可随时手动执行一次；开启与手动执行都记录真实摘要与审计。全局紧急暂停**不会**阻止本地清理，因为清理不发送消息、不调用模型、不处理媒体任务、不出网。
- 清理范围：超过保留期限的消息、媒体资产、转写、媒体任务、人格证据/版本快照中的证据引用、记忆与候选的来源消息 ID、超期未固定记忆，以及 `logs` 目录下严格匹配 `app.log.*` 的轮转日志。
- 记忆保留天数 `memory_retention_days` 允许 `0`（不自动删除）或 `1–3650`；`0` 不会被通用保留天数归一化改写。
- **清理先预览、再确认**：`GET /api/system/retention/preview` 只读返回将删除与保留的数量（含按批次上限截断后的估算），不取锁、不写审计、不更新上次运行；`POST /api/system/retention/run` 必须带 `confirm:"CLEANUP"`，缺失时不执行且无副作用。手动记忆清理的 `dry_run` 不要求确认词，真实删除同样要求 `CLEANUP`。调度器自动清理路径保持不变，不需要确认词。
- 日志保护：只处理 `app.log.*`，当前 `app.log` 始终保留；不删除其他文件，不跟随目录穿越。
- 引用保护：媒体按 SHA 去重，清理前会解析仍被保留消息引用的媒体；仍被引用的文件不删除，只清理来源引用，避免误删共享媒体。
- 派生数据先擦除、后删除消息：人格证据不足时降级 stable；无证据的待审提案标记 rejected；消息清理只擦除记忆/候选的来源 ID，**不改写记忆正文**；只有记忆保留期清理会删除未固定记忆正文（明确限制）。
- 清理不删除 outbox、审计、备份；分批执行并有单次批次上限，摘要标记是否 `truncated`。预览与实际运行之间可能有新消息写入，实际删除数以运行为准。
- **删除语义**：删除账号会清理其群、成员、消息、记忆/候选、outbox 与实例，先擦除人格证据与记忆来源引用，再按引用关系删除或保留媒体（共享媒体保留，未共享的删除文件并标记 `deleted`）。删除群只删除记忆/候选，历史消息保留但 `group_id` 置空；`pending`/`pending_approval` 待发消息改为 `cancelled` 并清空排期，不会再发送；`sending` 在途消息不改状态。删除人格会删除版本/特征/事件并解除群绑定，但不会因删除账号而连带删除人格。所有删除端点要求 `?confirm=DELETE`，审计只记录计数与名称，不含正文或路径。
- 删除证据消息会清理相关特征引用；媒体文件删除失败会记录计数与日志，不伪装成功。

## 11. 日志与审计

- 应用日志写入 `data/logs/app.log`，滚动保留；敏感字段通过脱敏过滤器处理。
- 请求/响应包包含 `request_id`，便于本地关联排查，不返回堆栈细节。
- 管理动作（账号、群、人格、Provider、预算、工具、插件、备份、暂停、设置、记忆、连接器安装/启停/配置/身份确认等）写入审计表。
- 预算告警写入 `budget.alert.warning` / `budget.alert.exceeded`；用量 CSV 导出写入 `usage.export`（含筛选条件与行数），便于核查谁在何时导出了什么范围的数据。
- 审计本身不保存明文 Token/API Key；请求参数中的敏感字段会被脱敏。
- 不要在生产环境开启调试级日志或将日志上传到不受信任的服务。

## 12. 事件响应

### 怀疑账号异常 / 风控

1. 在控制台或 `POST /api/system/pause-all` 启用**全局紧急暂停**。
2. 断开 OneBot 连接器（控制台或停止 NapCat）。
3. 检查「消息与用量」「审计」「QQ 接入状态」，确认最后收发与错误码。
4. 不要尝试绕过验证码或风控；由账号所有者自行处理。
5. 确认安全后先以「仅观察」恢复，再逐群恢复「仅 @」。

### 怀疑 Token / API Key 泄露

1. 全局暂停并断开连接器。
2. 在连接器端轮换 OneBot Token；在模型服务端吊销旧 API Key。
3. 在控制台更新凭证（旧密钥被新密钥替换）。
4. 检查审计、消息与 outbox 是否有异常发送。
5. 如怀疑数据库或宿主机已被入侵，视为 `CREDENTIAL_ENCRYPTION_KEY` 也可能泄露：
   - 生成新加密密钥并重启；
   - 重新录入全部凭证；
   - 重建数据库（必要时从可信备份恢复，但不要把旧密钥视为安全）。

### 怀疑数据泄露

1. 立即暂停所有回复，停止对外服务。
2. 隔离主机与备份，保留日志与审计证据。
3. 评估范围：群消息、人格数据、加密凭证、API Key 是否外泄。
4. 按适用法律与群规则通知相关方。
5. 修复入口后轮换所有凭证并重新部署。

## 14. 已知限制

- 本版本不提供端到端加密、数据库静态加密或硬件密钥保护；依赖宿主机安全。
- 不防御已攻陷的宿主机、恶意本地管理员或物理访问。
- 不保证外部连接器、模型服务或网络中间人的安全。
- 自动清理默认关闭；手动与设置页清理提供只读预览并要求 `CLEANUP` 确认，但预览只是某一时刻的快照，实际运行数量可能不同，执行后不可恢复。消息清理不覆盖 outbox、审计、备份与当前日志，也不会改写记忆正文，仅擦除来源 ID。手动记忆清理支持仅统计，但真实清理不可恢复；敏感记忆默认不导出。
- Provider Base URL 的 SSRF 防护只做语法与字面量判定，不解析 DNS，存在 DNS rebinding 残余风险；允许回环/私网是支持自建模型的必要折中。
- Schema 门禁是保守策略：旧版本备份会被拒绝；用户需用相同版本创建备份，或先升级并重新备份。缺少版本信息的备份为 `unknown`，允许恢复但带警告。
- Electron 权限处理器与 CSP 目前只通过静态单元测试与冒烟页面验证；真实系统权限交互、代码签名与自动更新校验不在本版本范围。
- 安装包未签名，Windows SmartScreen 可能提示未知发布者；没有自动更新，也没有安装包完整性签名。`BUILD_INFO.json` 的 SHA-256 只能证明构建机产物一致，不能替代发布者签名。
- NSIS 安装器/卸载器尚未在独立干净 Windows 机器执行；发布冒烟使用隔离的 `win-unpacked`，不创建快捷方式或安装注册表项。升级/回滚仍需人工按 [RELEASE.md](RELEASE.md) 演练。
- 未对真实 QQ 环境做安全联调；OneBot 仅通过进程内假服务器与协议测试验证。
- 远程管理的安全强度取决于部署方式、Token 强度与反向代理配置，而非本应用单独保证。
- 桌面壳不提供沙箱化第三方插件；源码版信任本仓库代码与本机 Python/Node 环境，安装版信任随包分发的冻结产物。安装依赖与获取安装包仍需用户自行确认来源与网络可信度。
